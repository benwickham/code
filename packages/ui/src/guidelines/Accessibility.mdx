# Accessibility

Accessibility is fundamental to the Modrinth Design System. We believe that great design is inclusive design, and every component is built with accessibility as a core requirement, not an afterthought.

## Our Commitment

The Modrinth Design System follows **WCAG 2.1 AA** standards and aims to provide an excellent experience for all users, including those who:

- Use screen readers or other assistive technologies
- Navigate using only a keyboard
- Have visual, auditory, motor, or cognitive disabilities
- Use high contrast modes or custom color schemes
- Access content on various devices and screen sizes

## Accessibility Principles

### 1. Perceivable
Information and UI components must be presentable to users in ways they can perceive.

**What we do:**
- Maintain 4.5:1 contrast ratios for normal text, 3:1 for large text
- Provide text alternatives for images and icons
- Support high contrast and dark modes
- Use multiple ways to convey information (color + icons + text)

### 2. Operable
UI components and navigation must be operable by all users.

**What we do:**
- Ensure all interactive elements are keyboard accessible
- Provide visible focus indicators
- Give users enough time to read content
- Avoid content that causes seizures or vestibular disorders

### 3. Understandable
Information and UI operation must be understandable.

**What we do:**
- Use clear, simple language
- Make text readable and understandable
- Make content appear and operate in predictable ways
- Help users avoid and correct mistakes

### 4. Robust
Content must be robust enough to be interpreted by a wide variety of user agents, including assistive technologies.

**What we do:**
- Use valid, semantic HTML
- Ensure compatibility with current and future assistive technologies
- Follow established web standards and best practices

## Component Accessibility

### Keyboard Navigation

All interactive components support keyboard navigation:

```
Tab          - Move to next focusable element
Shift + Tab  - Move to previous focusable element
Enter        - Activate buttons and links
Space        - Activate buttons, toggle checkboxes
Arrow Keys   - Navigate within component groups
Escape       - Close modals, dropdowns, and overlays
```

### Focus Management

- **Visible Focus**: All focusable elements have clear focus indicators
- **Focus Order**: Tab order follows logical reading sequence
- **Focus Trapping**: Modals and overlays trap focus appropriately
- **Focus Restoration**: Focus returns to trigger element when closing overlays

### Screen Reader Support

Components include proper ARIA attributes:

```html
<!-- Button with clear purpose -->
<button aria-label="Delete project 'My Mod'">
  <TrashIcon />
</button>

<!-- Form field with description -->
<label for="project-name">Project Name</label>
<input 
  id="project-name" 
  aria-describedby="name-help"
  required
/>
<div id="name-help">
  Choose a unique name for your project
</div>

<!-- Status with live updates -->
<div aria-live="polite" aria-atomic="true">
  Upload progress: 75% complete
</div>
```

## Implementation Guidelines

### Semantic HTML

Use semantic HTML elements for their intended purpose:

```html
<!-- Good: Semantic structure -->
<main>
  <header>
    <h1>Project Dashboard</h1>
    <nav aria-label="Main navigation">
      <ul>
        <li><a href="/projects">Projects</a></li>
        <li><a href="/settings">Settings</a></li>
      </ul>
    </nav>
  </header>
  
  <section aria-labelledby="recent-heading">
    <h2 id="recent-heading">Recent Projects</h2>
    <article>
      <h3>My Awesome Mod</h3>
      <p>A description of the mod...</p>
    </article>
  </section>
</main>

<!-- Avoid: Generic divs for everything -->
<div class="main">
  <div class="header">
    <div class="title">Project Dashboard</div>
    <div class="nav">
      <div class="nav-item">Projects</div>
      <div class="nav-item">Settings</div>
    </div>
  </div>
</div>
```

### ARIA Labels and Descriptions

Provide context for assistive technologies:

```html
<!-- Descriptive labels -->
<button aria-label="Sort projects by name">
  <SortIcon />
</button>

<!-- Expanded state for dropdowns -->
<button 
  aria-expanded="false" 
  aria-haspopup="menu"
  aria-controls="sort-menu"
>
  Sort Options
</button>

<!-- Form validation -->
<input 
  aria-invalid="true"
  aria-describedby="email-error"
/>
<div id="email-error" role="alert">
  Please enter a valid email address
</div>
```

### Color and Contrast

Never rely on color alone to convey information:

```vue
<!-- Good: Multiple indicators -->
<div class="status-success">
  <CheckIcon aria-hidden="true" />
  <span>Project approved</span>
</div>

<!-- Good: High contrast -->
<style>
.status-success {
  background: var(--color-success-light);
  color: var(--color-success-dark);
  border: 2px solid var(--color-success);
}
</style>

<!-- Avoid: Color only -->
<div style="color: green;">Approved</div>
```

## Testing Accessibility

### Automated Testing

Use these tools for automated accessibility testing:

```bash
# Install axe-core for automated testing
npm install --save-dev @axe-core/playwright

# Run accessibility tests
npm run test:a11y
```

### Manual Testing

#### Keyboard Testing
1. **Tab through the interface** - Can you reach all interactive elements?
2. **Use only keyboard** - Can you complete all tasks without a mouse?
3. **Check focus indicators** - Are they visible and clear?
4. **Test escape routes** - Can you exit modals and overlays?

#### Screen Reader Testing
1. **Use NVDA (Windows)** or **VoiceOver (Mac)** to navigate
2. **Listen to announcements** - Are they clear and helpful?
3. **Check reading order** - Does content flow logically?
4. **Test form interactions** - Are labels and errors announced?

#### Visual Testing
1. **Zoom to 200%** - Is content still usable?
2. **Test high contrast mode** - Are elements still distinguishable?
3. **Check color contrast** - Use tools like WebAIM's contrast checker
4. **Test with different color schemes** - Light, dark, high contrast

### Testing Checklist

Before releasing components, verify:

- [ ] **Keyboard Navigation**: All interactive elements are keyboard accessible
- [ ] **Focus Management**: Focus indicators are visible and logical
- [ ] **Screen Reader**: Content is announced clearly and completely
- [ ] **Color Contrast**: Meets WCAG 2.1 AA requirements (4.5:1 normal, 3:1 large)
- [ ] **Semantic HTML**: Uses appropriate HTML elements and ARIA attributes
- [ ] **Error Handling**: Errors are announced and clearly explained
- [ ] **Responsive**: Works at 200% zoom and on mobile devices
- [ ] **Motion**: Respects prefers-reduced-motion settings

## Common Patterns

### Loading States

Announce loading states to screen readers:

```vue
<template>
  <div>
    <button 
      :disabled="isLoading"
      :aria-describedby="isLoading ? 'loading-status' : undefined"
    >
      {{ isLoading ? 'Saving...' : 'Save Project' }}
    </button>
    
    <div 
      v-if="isLoading"
      id="loading-status"
      aria-live="polite"
      class="sr-only"
    >
      Saving your project, please wait...
    </div>
  </div>
</template>

<style>
.sr-only {
  position: absolute;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip: rect(0, 0, 0, 0);
  white-space: nowrap;
  border: 0;
}
</style>
```

### Form Validation

Provide clear, accessible error messages:

```vue
<template>
  <div class="form-field">
    <label for="project-name">
      Project Name
      <span aria-label="required">*</span>
    </label>
    
    <input
      id="project-name"
      v-model="projectName"
      :aria-invalid="hasError"
      :aria-describedby="hasError ? 'name-error' : 'name-help'"
      required
    />
    
    <div id="name-help" class="help-text">
      Choose a unique name for your project
    </div>
    
    <div 
      v-if="hasError"
      id="name-error"
      role="alert"
      class="error-text"
    >
      Project name is required and must be at least 3 characters
    </div>
  </div>
</template>
```

### Modal Dialogs

Implement proper focus management:

```vue
<template>
  <div 
    v-if="isOpen"
    class="modal-overlay"
    @click="closeModal"
  >
    <div 
      class="modal"
      role="dialog"
      aria-modal="true"
      aria-labelledby="modal-title"
      aria-describedby="modal-description"
      @click.stop
    >
      <header>
        <h2 id="modal-title">Delete Project</h2>
        <button 
          aria-label="Close dialog"
          @click="closeModal"
        >
          <CloseIcon />
        </button>
      </header>
      
      <div id="modal-description">
        This action cannot be undone. Are you sure you want to delete this project?
      </div>
      
      <footer>
        <button @click="closeModal">Cancel</button>
        <button class="danger" @click="deleteProject">
          Delete Project
        </button>
      </footer>
    </div>
  </div>
</template>

<script setup>
import { onMounted, onUnmounted } from 'vue'

// Focus management
onMounted(() => {
  // Focus first interactive element
  const firstButton = document.querySelector('.modal button')
  firstButton?.focus()
  
  // Trap focus within modal
  document.addEventListener('keydown', handleKeyDown)
})

onUnmounted(() => {
  document.removeEventListener('keydown', handleKeyDown)
})

function handleKeyDown(event) {
  if (event.key === 'Escape') {
    closeModal()
  }
  
  // Implement focus trapping logic
  if (event.key === 'Tab') {
    // ... focus trap implementation
  }
}
</script>
```
